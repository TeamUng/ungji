## Conventions

### Logging

The project has centrally configured logging (console + Better Stack + Discord alerts for errors). Any time you add or modify code with observable behavior, include logging.

**Get a logger:**

    from app.core.logging import get_logger
    logger = get_logger(__name__)

**Do not use `print()` anywhere in `app/`.**

**Levels:**

- `logger.debug(...)` — verbose diagnostic; disabled in prod
- `logger.info(...)` — normal operational events (request received, task started, external call made)
- `logger.warning(...)` — unexpected but recoverable (retry triggered, fallback used, deprecated path)
- `logger.error(...)` — something failed → automatically sends to Discord
- `logger.exception("...")` — inside `except:` blocks; includes the stack trace
- `logger.critical(...)` — reserved for "wake someone up"

**Pass structured data via `extra=`, not f-strings:**

    logger.info("User signed up", extra={"user_id": user.id})   # good
    logger.info(f"User signed up: {user.id}")                    # works but worse

**Never log:**
- Secrets, API keys, tokens
- Full request bodies in INFO level (DEBUG is OK)
- User PII beyond what's necessary

**When to log:**
- Entry and result of external calls (DB, Upstage, Supabase)
- Start and end of significant operations
- All exceptions before re-raising (`logger.exception(...)` in `except`)

### Config / environment

- All configuration lives in `app/core/config.py` as the `Settings` pydantic-settings class
- Add new env vars there first, then in `.env.example` with an empty value, then wherever you consume them
- Never read from `os.environ` directly in app code — always import `settings` from `app.core.config`
- Never commit `.env`

### Tests

- One test file per module of interest
- Prefer FastAPI `TestClient` for endpoint tests
- Don't mock what you're testing; do mock external services (Upstage, Supabase, Discord)

### Commits

- Conventional commits in Korean: `feat:`, `fix:`, `docs:`, `chore:`
- See `COMMIT_CONVENTION.md` (or ask the human for the commit style if absent)
- Never include AI signatures / "Generated by..." in commit messages

### Things NOT in this project (for now)

- No ruff, black, mypy, or other linters/formatters
- No pre-commit hooks
- No CI
- No Docker
- No CORS (frontend comes later)
- SSE streaming: POST /chat 응답에서 사용 예정 (T10 구현 시)
