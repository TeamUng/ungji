# 시나리오 기대 출력 기준

> 목적: 기획 의도와 실제 LLM 출력의 차이를 비교하기 위한 기준 문서다.
> 문장을 하드코딩하려는 문서가 아니라, 프롬프트·가드레일·내부 구조를 바꿀 때 "기획 의도에서 벗어났는지" 검수하는 기준이다.

관련 파일:

- 자동 평가 기준: `scripts/scenarios/expected_cases.json`
- 시나리오 실행기: `scripts/run_scenarios.py`
- 실행 결과: `scripts/results/scenario_transcript_*.md`, `scripts/results/scenario_eval_*.csv`

---

## 1. 활용 방식

### 문서 기준

팀원이 아래를 합의한다.

- 케이스별 학생 유형과 학년
- TP1~TP5에서 기대하는 역할
- 학생에게 보여도 되는 출력
- 절대 노출되면 안 되는 출력

### 자동 평가 기준

`scripts/scenarios/expected_cases.json`은 이 문서의 핵심 조건을 구조화한 파일이다.
`scripts/run_scenarios.py`는 실제 LLM 출력에 대해 `must_include` / `must_not_include` / 선택지 개수 등을 검사한다.

### 프롬프트 개선 기준

시나리오 transcript에서 금지 표현이 나오면 다음 순서로 고친다.

1. 프롬프트 출력 계약 보강
2. motivator/helper 역할 경계 보강
3. guardrail repair 보강
4. 필요하면 내부 decision/renderer 구조 보강

---

## 2. 공통 금지 출력

학생 화면에는 아래 표현이 노출되면 안 된다.

- 내부 판단: `추천 이유`, `내부 이유`, `reason_for_llm`
- 실행 지시: `학생 반응을 기다린 후`, `실제 출력`, `도구 호출`
- 도구/구조: `send_text`, `send_causes`, `JSON`, `tool`
- 분류명: `저성취`, `고성취`, `불성실`, `세그먼트`, `유형`
- 없는 콘텐츠: 새 문제, 새 예시, 교과서 페이지, 숙제, 미션

TP3에서는 특히 아래가 금지다.

- `첫 식 잡아줄게`
- `어디가 어려워?`
- `같이 풀어줄게`
- 문제풀이 힌트로 바로 진입하는 표현

TP3는 도움 요청이 아니라 프론트 이탈 이벤트이기 때문이다.

## 3. Case 1 - 고성취/불성실 저학년 (국어 시연)

| 항목 | 값 |
|---|---|
| student_id | `lower-high-lazy` (mock_students.json 데이터 교체 예정) |
| 이름 | 성준 |
| 학년 | 2학년 |
| 학생 유형 | 잘함+불성실 |
| 시연 과목 | 국어 |
| 국어1 (중) | 문단의 짜임 - 긴글 이해하기 — TP1 추천 |
| 국어2 (고) | 문단의 짜임 - 중심 문장과 뒷받침 문장 찾기 — TP2 추천 |
| 수학 | 네자리 수 (이미 완료, 시연 안 함) |
| 시연 문제 ID | `lower_korean_paragraph_001` (중) → `lower_korean_paragraph_002` (고) |

기획 의도:

- 잘하지만 쉽게 이탈하는 학생.
- 잘하는 국어로 시작 → 정답 칭찬 → 심화 도전.
- 이탈 시도 발생 시 TP3로 잡고 학습 복귀.
- 심화에서 오답 시 뽀롱이 트리거로 TP4 진입 → 짧게 도와주고 종료 인사.

### 시연 플로우

| 순 | 단계 | 트리거 | TP |
|---|---|---|---|
| 1 | 홈 진입 → 국어1(중) 추천 | (init) | TP1 |
| 2 | 국어1 문제 → 정답 표시 | 학생 정답 제출 (정답: 2번) | (프론트 표시) |
| 3 | 정답 칭찬 + 국어2(고) 추천 | (이전 단계 직후) | TP2 |
| 4 | 학생 이탈 시도 → 방지 | 이탈 이벤트 | TP3 |
| 5 | 국어2 진입 → 강의 학습 (가정/연기) | 학생 진입 | (학습 시스템) |
| 6 | 국어2 문제 → 오답 표시 | (오답 상정, 프론트 하드코딩) | (프론트 표시) |
| 7 | 학생 뽀롱이 작동 → "어렵니?" → 도움 | 학생 트리거 | TP4 |
| 8 | 이해 완료 → 학생 나가기 → 종료 인사 | 학생 종료 (TP3 발동 X) | (TP 매핑 없음, 종료 인사 멘트) |

### 1. TP1 - 홈 진입 → 국어1(중) 추천

입력:

```json
{
  "student_id": "lower-high-lazy",
  "use_case": "talk",
  "current_touchpoint": "tp1",
  "message": {"type": "init", "content": ""}
}
```

기대:

- 잘하는 국어 `문단의 짜임 - 긴글 이해하기`부터 시작 유도
- `금세`, `한 문제만`처럼 짧게 끝낼 수 있다는 톤
- 새 문제·새 과제 생성 금지

예시:

```text
성준아, 오늘은 잘하는 국어부터 시작해보자.
긴글 이해하기, 금세 풀 수 있어.
```

### 2. (프론트 표시) - 국어1 정답 표시

학생 입력 예시:

```text
(정답: 2번 선택 — "나무와 물")
```

처리:

- 정답 표시는 프론트가 처리. 코치 자동 응답 없음.

### 3. TP2 - 정답 칭찬 + 국어2(고) 추천

가정: 직전에 국어1 정답이 표시된 상태.

기대:

- 짧은 칭찬으로 시작
- 다음 단원 `중심 문장과 뒷받침 문장 찾기` 안내
- 다음 콘텐츠 이동 버튼 강조 (프론트 처리)
- 새 단원 생성 금지

예시:

```text
정답! 글의 흐름 잘 잡았어.
어려운 거 한 문제만 더 도전해볼까? "중심 문장과 뒷받침 문장 찾기"야.
```

### 4. TP3 - 이탈 방지

트리거:

- 학생 자연어 입력이 아니라 프론트 이벤트 (나가기 버튼·뒤로가기·이탈 시도·무응답)

기대:

- 남은 양이 작다는 점을 알려준다 (`오늘 하나만 더하면 끝`)
- 문제풀이 도움으로 넘어가지 않는다.

예시:

```text
성준아, 한 문제만 더 풀면 오늘 끝이야.
마저 끝내고 편하게 쉬자.
```

### 5. (학습 시스템) - 국어2 진입 → 강의 학습

가정: 학생이 다음 콘텐츠 버튼을 눌러 국어2로 이동, 강의를 학습한 상태로 연기.

→ 코치 응답 없음.

### 6. (프론트 표시) - 국어2 오답 표시

처리:

- 정답·오답 표시는 프론트 하드코딩으로 처리.
- 코치 자동 진입 X. 학생이 뽀롱이를 누를 때까지 대기.

### 7. TP4 - 뽀롱이 트리거 → 도움

트리거:

- 학생이 뽀롱이를 드래그/클릭 (백엔드 입력 형식 보류)

기대:

- 첫 응답은 "어렵니?" 같이 부담 낮은 진입
- 막힌 지점 선택지 3개 이하로 제시
- 답을 바로 알려주지 않고 단계 힌트 1개부터
- 짧게 마무리 가능하게 (학생 종료를 방해하지 않음)

좋은 선택지 예:

- 문제가 무슨 말인지 모르겠어요
- 어디를 봐야 할지 모르겠어요
- 그냥 답이 헷갈려요

좋은 흐름 예:

```text
어렵니? 어디가 막혔는지 골라볼래?
```

### 8. (종료 인사) - 정상 종료

가정: 학생이 이해 완료 후 나가기 버튼 → TP3 발동 X.

기대:

- TP 매핑 없음. 종료 자체에 뽀롱쌤 페르소나 인사 멘트 1개만 출력.
- 도전한 점 짧게 인정
- 새 학습 권유 금지

예시:

```text
성준아, 오늘 어려운 것까지 끝까지 한 게 멋졌어.
잘 마쳤으니 편히 쉬어. 안녕, 뽀롱~
```

## 4. Case 2 - 저성취/성실 고학년 (수학 시연)

| 항목 | 값 |
|---|---|
| student_id | `upper-low-diligent` (mock_students.json 데이터 교체 예정) |
| 이름 | 아연 |
| 학년 | 6학년 |
| 학생 유형 | 못함+성실 |
| 시연 과목 | 수학 |
| 수학 (가장 취약) | 비와 비율 — TP1 추천 |
| 국어 (2번째 취약) | 정보와 표현 판단하기 — TP2 추천 |
| 영어 / 과학 | 이미 완료, 시연 안 함 |
| TP4 문제 | `math_ratio_saltwater_001` (단원명을 "비와 비율"로 매핑, 내용 동일) |

기획 의도:

- 열심히 하지만 개념이 약한 학생.
- 가장 취약한 수학부터 단계 힌트로 끝까지 도달하게 한다.
- 답을 바로 던지지 않고 스스로 사고하게 유도한다.
- 성실한 학생이라 이탈(TP3)은 발생하지 않는다.
- 마무리는 복습 동선으로 자연스럽게 연결.

### 시연 플로우

| 순 | 단계 | 트리거 | TP |
|---|---|---|---|
| 1 | 홈 진입 → 수학(가장 취약) 추천 (비와 비율) | (init) | TP1 |
| 2 | 수학 소금물 문제 도움 | 학생이 막힘 | TP4 |
| 3 | 수학 완료 → 국어(2번째 취약) 추천 (정보와 표현 판단하기) | (단원 완료 가정) | TP2 |
| 4 | 국어 완료 → "복습하러 가기" 안내 → 종료 | 학생 복습 버튼 클릭 | TP5 |

### 1. TP1 - 홈 진입 → 수학 추천

입력:

```json
{
  "student_id": "upper-low-diligent",
  "use_case": "talk",
  "current_touchpoint": "tp1",
  "message": {"type": "init", "content": ""}
}
```

기대:

- 가장 취약한 수학 `비와 비율`부터 시작 유도
- 어렵지만 차근차근 하면 된다는 안정감
- 새 문제·새 과제 생성 금지

예시:

```text
아연아, 오늘은 수학 비와 비율부터 차근차근 시작해보자.
조금 어려워 보여도 한 단계씩 보면 충분히 할 수 있어.
```

### 2. TP4 - 수학 문제 도움

입력:

```json
{
  "student_id": "upper-low-diligent",
  "use_case": "learning",
  "current_touchpoint": "tp4",
  "message": {"type": "init", "content": "math_ratio_saltwater_001"}
}
```

기대:

- 막힌 지점 선택지 3개 이하
- 소금물 비율 문제와 해설만 사용
- `소금 ÷ 소금물`을 학생이 직접 떠올리게 유도
- 단계 힌트, 답 직접 노출 금지

좋은 선택지 예:

- 문제가 이해가 안돼요
- 어떻게 푸는지 모르겠어요
- 계산이 어려워요

좋은 흐름 예:

```text
좋아, 핵심은 "소금이 소금물 전체에서 얼마나 차지하나"를 보는 거야.
(가)부터 보면 소금은 37g, 소금물은 148g이야.
먼저 어떤 식을 세우면 좋을까?
```

### 3. TP2 - 수학 완료 → 국어 추천

기대:

- 수학 완료를 인정
- 다음은 두 번째로 취약한 국어 `정보와 표현 판단하기`로 유도
- 차근차근 해볼 수 있다는 톤

예시:

```text
아연아, 어려운 수학을 끝까지 해낸 게 정말 좋아.
다음은 국어 정보와 표현 판단하기로 이어가 보자.
문장을 차근차근 나누면 충분히 할 수 있어.
```

### 4. TP5 - 국어 완료 → 복습 안내 → 종료

트리거:

- `오늘 학습목록 완수` 불리언이 true가 되면 TP5 진입.
- 출력은 코치 멘트 + "복습하러 가기" 버튼.

기대:

- 오늘 끝까지 해낸 점 인정
- 복습 동선으로 자연스럽게 연결
- 새 학습 권유 금지

예시:

```text
아연아, 오늘 정말 잘 해냈어.
어려운 수학도 끝까지 한 게 좋아.
이제 복습하러 가서 가볍게 다시 보자.
```
