# 데모 프론트 분리 전략

## 목표

발표 시연은 끊기지 않고 안정적으로 보여주되, 실제 백엔드 코칭 로직에는 시연용 고정 흐름을 박지 않는다.

## 왜 이렇게 나누는가

- 발표에서는 화면 흐름이 끊기지 않는 것이 가장 중요하다.
- 백엔드 응답은 LLM, 네트워크, 서버 상태에 따라 흔들릴 수 있다.
- 시연 케이스를 백엔드에 하드코딩하면 실제 서비스 로직과 데모 로직이 섞인다.
- 따라서 시연 안정성은 프론트 데모 모드가 책임지고, 백엔드는 범용 응답 생성기로 유지한다.

## 모드

### hybrid mode

기본 데모 모드다.

- URL 예: `/tp-demo?case=lower-korean`
- 프론트가 시연 상태 흐름을 제어한다.
- 백엔드 응답을 우선 사용한다.
- 백엔드 응답 실패 또는 부적절한 경우 프론트 fallback 문구를 사용한다.

### script mode

발표 현장 비상용 완전 시연 모드다.

- URL 예: `/tp-demo?case=lower-korean&mode=script`
- 백엔드를 호출하지 않는다.
- 프론트에 정의된 고정 멘트와 고정 흐름만 사용한다.
- 인터넷, API, 백엔드 상태와 무관하게 시연을 이어갈 수 있다.

## 책임 분리

### 공통 프론트

일반 화면과 데모 화면이 함께 공유한다.

- 화면 레이아웃
- 문제 카드 UI
- 채팅창 UI
- 뽀롱 위치와 시각 배치
- 버튼 크기와 시각 스타일
- 오른쪽 영역 구성

### 데모 전용 프론트

`/tp-demo`에서만 사용한다.

- 성준/아연 케이스 선택
- TP1~TP5 시연 흐름
- 시연용 고정 멘트
- 시연용 선택지
- 정답/오답 고정 처리
- script mode fallback
- 발표자용 숨은 단축키

### 백엔드

백엔드는 데모 케이스별 고정 흐름을 알지 않는다.

- `flow_event`, `answer_result`, `today_tasks_completed` 같은 범용 context만 받는다.
- `demo_case_id`처럼 특정 시연 케이스를 직접 가리키는 값은 받지 않는다.
- 실제 코칭 응답 생성과 정책 판단을 담당한다.

## 발표 운영 원칙

- 평소 리허설은 hybrid mode로 백엔드 연결 상태까지 확인한다.
- 발표 직전 또는 현장 불안정 상황에서는 script mode로 전환한다.
- 화면에는 데모 조작 버튼을 보이지 않는다.
- 필요 시 숨은 단축키로 케이스 전환과 리셋만 수행한다.

## 예정 단축키

- `1`: 성준 케이스로 전환하고 처음부터 시작
- `2`: 아연 케이스로 전환하고 처음부터 시작
- `R`: 현재 케이스를 처음부터 리셋

입력창, textarea, select에 포커스가 있을 때는 단축키를 무시한다.
