# 웅진씽크빅 스마트올 초등학생 맞춤형 AI 학습코치 챗봇

> **챗봇은 연결다리(있는 기능의 연결다리!! 문제 생성보다는 있는 문제 기반이라는 설정. 우리는 테스트용 예제를 기반으로 개발)**

---

## 1. 요구사항

### 1-1. 무엇을 만들 건지

웅진씽크빅 스마트올 태블릿 환경에서 초등학생 1~6학년이 학습을 시작하거나, 학습 중 막혔을 때 도움을 받을 수 있는 **AI 학습코치 챗봇 에이전트**를 만든다.

이 챗봇은 단순히 정답을 알려주는 챗봇이 아니라, 학생의 학습 상태와 유형에 따라 다음 역할을 수행한다.

- 홈화면 진입 시 학생에게 먼저 말을 걸고 오늘 할 학습을 제안한다. (오늘 해야 할 과제를 순서 제시하고 바로 시작하도록 유도. 버튼 바로 노출)
- 학습 중 학생이 막혔을 때 막힌 원인을 물어보며 끌어내고 단계별로 도움을 준다.
- 학생 유형, 학년, 학습 상황에 따라 말투와 선택지를 다르게 제공한다. (프롬프트로 제어)
- 텍스트 중심으로 응답하되, 저학년 또는 개념 이해가 어려운 경우에는 채팅 내 이미지 카드를 활용할 수 있다.
- MVP는 실제 스마트올 연동 없이, 태블릿 화면 비율에 맞춘 웹 기반 챗봇 UI 목업으로 구현한다.

### 1-5. 홈화면 챗봇 선택지 개인화

홈화면 진입 시 챗봇은 모든 학생에게 같은 선택지를 보여주지 않는다.

학생 유형 클러스터와 최근 학습 상태를 기반으로 현재 필요한 학습 행동을 우선 제안한다.

| 판단된 상태 | 홈화면 우선 선택지<br>(우리가 제공하는 기능이 아닌, 있는 기능으로 유도하고 이동시켜주는 기능) | 제공 이유 |
| --- | --- | --- |
| 고성취 + 성실 | • 오늘의 심화 문제 도전하기<br>• 실생활 적용 문제 풀기<br>• 내가 약한 단원 확인하기 | 기본 학습은 이미 잘 수행하므로 흥미 유지와 사고 확장이 필요하다. |
| 고성취 + 불성실 | • 5분만 도전 문제 풀기 (문구만)<br>• 오늘 할 것 AI가 골라주기<br>• 어제 하던 학습 이어하기 | 실력은 있지만 루틴이 약하므로 긴 학습보다 짧고 명확한 시작점이 필요하다. |
| 저성취 + 성실 | • 쉬운 설명으로 다시 배우기<br>• 한 문제를 단계별로 같이 풀기<br>• 내가 어디서 막혔는지 확인하기 | 노력은 하고 있으나 이해가 부족한 상태이므로 실패감을 줄이고 막힘 원인을 구조화해야 한다. |
| 저성취 + 불성실 | • 3분만 가볍게 시작하기 (문구만)<br>• 아주 쉬운 문제 1개만 풀기<br>• 재미있는 예시로 먼저 보기 | 학습 시작 자체가 어려우므로 성취 기준을 낮추고 즉시 성공 경험을 제공해야 한다. |
| ~~성급형~~ | ~~• 문제 다시 읽고 풀기<br>• 실수 줄이는 연습하기 (실수로 틀린 문제 다시풀기로 이동하기 기능)<br>• AI와 조건 하나씩 확인하기~~ | ~~맞힐 수 있었지만 실수하는 학생이므로 풀이 태도 교정이 필요하다.~~ |
| ~~개념 부족형~~ | ~~• 개념 쉽게 다시 보기<br>• 예시로 이해하기<br>• 비슷한 문제 같이 풀기~~ | ~~반복 오답의 원인이 개념 미이해일 가능성이 높으므로 설명 방식 전환이 필요하다.~~ |
| ~~회피형~~ | ~~• 제일 쉬운 단계부터 하기<br>• 부담 없이 1문제만 풀기<br>• AI가 같이 풀어주기~~ | ~~회피와 이탈을 줄이기 위해 학습 단위를 작게 만들고 심리적 부담을 낮춰야 한다.~~ |

### 1-6. 학년별 챗봇 말투와 페르소나

챗봇 캐릭터 디자인은 **1개로 통일**한다.

다만 학년, 상황, 학생 유형에 따라 말투, 표정, 메시지 톤을 다르게 제공한다.

| 구분 | 발달·학습 특성 해석 | 챗봇 말투 방향 | 예시 |
| --- | --- | --- | --- |
| 1~2학년 | 학교생활 적응, 짧은 집중, 구체적 지시 필요. 문제 해결보다 함께 시작하기가 중요 | 짧고 다정하게, 놀이·칭찬 중심, 한 번에 하나만 제시 | "좋아! 딱 하나만 같이 해보자." / "여기서 먼저 동그라미 칠 곳을 찾아볼까?" |
| 3~4학년 | 읽기·계산·개념 설명이 본격화되는 구간. 스스로 말로 설명하는 연습 필요 | 친근하지만 조금 더 구조화. 선택지를 주고 이유를 말하게 유도 | "좋아, 먼저 문제에서 묻는 걸 찾아보자. ① 계산 ② 비교 ③ 설명 중 뭐에 가까울까?" |
| 5~6학년 | 추상적 사고, 자기주도성, 자존감 민감도가 커지는 시기. 설명의 논리성과 존중감 중요 | 차분하고 존중하는 코치형. 부드러운 해요체 고려 | "괜찮아. 먼저 무엇과 무엇을 비교하는 문제인지 같이 찾아보자." / "네 풀이 방향은 좋아. 다만 조건 하나를 더 확인해보자." |

### 1-7. 퓨삿 프롬프팅을 위한 케이스 (TDD) - MVP 시연 케이스

이번 MVP에서는 학년과 학생 유형의 대비가 명확한 2개 케이스를 시연한다.

| 케이스 | 대상 | 과목 | 단원/활동 | 학생 유형 | 핵심 시연 가치 |
| --- | --- | --- | --- | --- | --- |
| 케이스 1 | 초등 1~2학년 | 국어 | 짧은 글 읽기 + 주인공 마음/상황 고르기 | 공부하지 않는 학생 / 저성취 + 불성실 + 회피형 | 학습 시작 장벽을 낮추고, 선택지 기반으로 짧게 학습을 시작하게 만드는 흐름 |
| 케이스 2 | 초등 5~6학년 | 수학 | 비율/비례식 | 성실하지만 성취가 낮은 학생 / 저성취 + 성실 + 개념 부족형 | 막힘 원인을 진단하고, 개념을 쉬운 설명과 단계별 풀이로 보정하는 흐름 |

| 성실하지만 성취가 낮은 학생 | 정답률 낮음 + 학습 완료율/재도전률 높음 + 건너뛰기 적음 | 풀이 시간은 길고 정답률은 낮지만 오답 후 재도전함 | 쉬운 설명, 단계별 풀이, 막힘 원인 진단 제공 |
| 공부하지 않는 학생 | 정답률 낮음 + 학습 완료율 낮음 + 건너뛰기/이탈 많음 | 문제를 자주 건너뛰고 미완료 학습 수가 많음 | 3분 학습, 쉬운 문제 1개, AI가 골라주기 등 초소형 진입 선택지 제공 |
| ~~성급형 학생~~ | ~~빠른 제출 + 맞힐 수 있었지만 틀린 문제 많음~~ | ~~예측상 맞힐 수 있었으나 실제 오답, 풀이 시간이 지나치게 짧음~~ | ~~문제 다시 읽기, 조건 확인, 검산 유도 중심 코칭~~ |
| ~~개념 부족형 학생~~ | ~~긴 풀이 시간 + 낮은 정답률 + 몰라서 틀린 문제 많음~~ | ~~오래 고민했지만 오답, 같은 유형 반복 오답~~ | ~~쉬운 설명, 비유, 예시, teach-back 질문 제공~~ |
| ~~회피형 학생~~ | ~~건너뛰기 많음 + 특정 단원 반복 회피 + 학습 중 이탈~~ | ~~특정 단원 반복 건너뛰기, 오답 후 이탈~~ | ~~쉬운 문제부터 시작, 짧은 세션, 흥미 기반 설명 제공~~ |

### 2-5. 퓨샷 프롬프팅을 위한 케이스 (TDD) 케이스 1 상세 시나리오

#### 초등 1~2학년 / 국어 / 짧은 글 읽기 + 주인공 마음·상황 고르기

#### 공부하지 않는 학생 / 저성취 + 불성실

##### A. 홈화면 진입 시 챗봇 흐름

| 단계 | 흐름 |
| --- | --- |
| 1 | 학생이 스마트올 홈화면에 진입 |
| 2 | 챗봇이 먼저 환영 메시지를 제공 |
| 3 | 최근 학습 완료율 낮음, 미시작 학습 많음, 국어 활동 회피 경향을 바탕으로 회피형 상태로 판단 |
| 4 | 긴 학습이 아니라 짧고 쉬운 국어 활동을 제안 |
| 5 | 선택지 버튼 제공 |
| 6 | 학생이 선택지를 누르면 바로 짧은 국어 활동으로 진입 |

##### 홈화면 선택지 예시

| 선택지 | 이유 |
| --- | --- |
| 1분만 짧은 글 읽어보기 | 학습 시작 부담을 낮춤 |
| 아주 쉬운 문제 1개만 풀기 | 즉시 성공 경험 제공 |
| 그림 보고 주인공 마음 골라보기 | 저학년에게 친숙하고 진입장벽이 낮음 |
| AI가 오늘 할 것 골라주기 | 스스로 선택하기 어려운 회피형 학생에게 적합 |

##### B. 학습 중 챗봇 클릭 시 흐름

| 단계 | 흐름 |
| --- | --- |
| 1 | 학생이 짧은 글 읽기 활동 중 멈춤 |
| 2 | 문제를 건너뛰거나 오랫동안 답하지 않음 |
| 3 | 학생이 챗봇 도움 버튼 클릭 |
| 4 | 챗봇이 "어디가 어려워?"를 직접 묻기보다 선택지를 제공 |
| 5 | 학생이 `글 읽기 싫어`, `무슨 말인지 모르겠어`, `답 고르기 어려워` 중 선택 |
| 6 | 챗봇이 글을 더 짧게 쪼개거나 쉬운 표현으로 바꿔서 설명 |
| 7 | 주인공 마음을 고르는 쉬운 선택지 제공 |
| 8 | 맞히면 즉시 칭찬하고 다음 1문제만 제안 |

##### 학습 중 도움 선택지 예시

| 선택지 | 챗봇 대응 |
| --- | --- |
| 글이 너무 길어 | 문장을 한 줄씩 나눠서 보여줌 |
| 무슨 상황인지 모르겠어 | 상황을 쉬운 말로 다시 설명하고 이미지 카드 제공 가능 |
| 주인공 마음을 모르겠어 | 표정/행동 단서를 알려주고 선택지를 좁힘 |
| 그냥 하기 싫어 | "한 문제만 같이 해보자"로 초소형 목표 제안 |

### 2-6. 퓨샷 프롬프팅을 위한 케이스 (TDD) 케이스 2 상세 시나리오

#### 초등 5~6학년 / 수학 / 비율·비례식

#### 성실하지만 성취가 낮은 학생 / 저성취 + 성실

##### A. 홈화면 진입 시 챗봇 흐름

| 단계 | 흐름 |

| 3 | 최근 수학 정답률 낮음, 학습 완료율 높음, 재도전률 높음, 풀이 시간이 김 |
| 4 | 성실하지만 개념 이해에 어려움을 겪는 학생으로 판단 |

| --- | --- |

| 내가 어디서 헷갈렸는지 확인하기 | 막힘 원인 진단으로 연결 |

##### B. 학습 중 챗봇 클릭 시 흐름

| 단계 | 흐름 |
| --- | --- |
| 1 | 학생이 비율/비례식 문제를 푸는 중 오답 제출 |

| 3 | 학생이 챗봇 도움 버튼 클릭<br>(챗봇은 어딘가에 고정되어 살짝씩만 움직임) |
| 4 | 챗봇이 막힘 원인을 진단 |
| 5 | `비율 뜻이 헷갈려`, `식을 어떻게 세우는지 모르겠어`, `계산하다가 틀렸어` 같은 선택지 제공 |
| 6 | 학생 선택에 따라 쉬운 비유 설명 또는 단계별 풀이 제공 |

| 10 | 아이의 설명이 맞으면 칭찬 / 아이의 설명이 부족하면 칭찬 + 부족한 부분 추가 설명 |

##### 학습 중 도움 선택지 예시

챗봇이 대응할 때 "스마트올 내 실제 해설 데이터 바탕으로 아래 대응"

| 선택지 | 챗봇 대응 |
| --- | --- |
| 비율 뜻이 헷갈려 | 일상 비유로 비율 개념 재설명<br>(해설 등 내부데이터에 없다면 제공X<br>대부분 있다고 가정) |
| 어떤 수끼리 비교해야 할지 모르겠어 | 문제에서 기준량과 비교량을 찾게 유도 |
| 식을 어떻게 세우는지 모르겠어 | 비례식 구조를 단계별로 안내 |
| 계산하다가 틀렸어 | 개념 설명보다 계산 과정 검산 유도 |

### 2-8. (후순위) 부모용 요약 기능

부모용 요약은 MVP 핵심 기능이 아니라 **후순위 기능**으로 배치한다.

- 시간이 된다면 챗봇 대화 종료 후, 챗봇 UI 안에서 `오늘의 코칭 요약` 형태로 간단히 제공한다.

| 항목 | 내용 |
| --- | --- |
| 우선순위 | 후순위 |
| 제공 위치 | 챗봇 대화 종료 후 |
| 제공 형식 | 간단한 텍스트 요약 카드 |
| 목적 | 부모가 아이가 무엇을 했고, 어디에서 도움을 받았는지 확인 |
| 포함 정보 | 오늘 시도한 학습, 막힌 지점, 챗봇이 제공한 도움, 다음 추천 행동 |
| 제외 사항 | 부모용 상세 대시보드, 장기 분석 리포트, 별도 통계 화면 |

### 2-9. (후순위) 학생 유형을 학부모가 정하게 하기

목적: 학생 유형진단을 학부모에게 유보해 학부모 시선에서의 오프라인 콘텍스트를 판단근거로 삼고, 책임 회피 효과를 달성.

기능: 스마트올 이용 데이터 기반, 학생 유형 진단 기준(우리가 설정한)으로 학생의 유형을 추리고, 그걸 학부모에게 옵션으로 제시하고 선택하게함.
왜 그런 옵션이 나왔는지 근거를 충분히 설명, 그리고 이 유형을 골랐을 때 제공되는 피드백의 스타일과 효과를 명시.

## 3. 제약조건(개발 제외 요소)

| 제약조건 | 내용 |
| --- | --- |
| 스마트올 실제 연동 없음 | 실제 스마트올 서비스, 학습 데이터, 회원 정보와 연동되지 않는다. (목업으로 진행) |
| 실제 학생 데이터 사용 없음 | 개인정보 및 실제 학습 로그를 사용하지 않고 목업 데이터를 사용한다. |
| 챗봇 UI 내부 구현 중심 | MVP에서 구현 가능한 범위는 챗봇 UI 내부로 제한한다. |
| 별도 화면 구현 최소화 | 챗봇 UI 밖의 상세 리포트, 별도 대시보드, 복잡한 설정 화면은 구현하지 않는다. |
| 문제 생성 엔진 구현 없음 | 실제 교육과정 기반 문제 자동 생성 엔진은 구현하지 않는다. 필요한 문제는 시나리오 기반 목업으로 작성한다. |
| 캐릭터 디자인 다양화 없음 | 캐릭터봇은 단일 디자인을 사용하고, 학년/상황별로 말투와 표정만 다르게 표현한다. |
| 부모용 상세 대시보드 없음 | 부모용 기능은 후순위이며, 구현하더라도 챗봇 종료 후 간단 요약 수준으로 제한한다. |
| 내부 클러스터명 비노출 | 학생에게 "불성실", "저성취", "회피형" 같은 내부 분류명을 직접 노출하지 않는다. |
| 정답 바로 제공 지양 | 정답을 바로 알려주기보다 막힘 원인 진단, 힌트, 쉬운 설명, 단계별 풀이 중심으로 돕는다. |
| 부정적 표현 금지 | 학생을 평가하거나 낙인찍는 표현을 사용하지 않는다. |
| UI 요소 제한 | 텍스트 메시지, 선택지 버튼, 간단한 이미지 카드, 단계별 힌트 카드만 사용한다. |

| 목업 데이터 적용 | 최근 정답률, 학습 완료율, 건너뛰기 횟수, 풀이 시간, 오답 원인, 오답 후 재도전 여부 데이터를 목업으로 보유해야 한다. |
| 학생 유형 판단 | 목업 데이터를 기반으로 최소 2개 MVP 케이스의 학생 유형을 구분할 수 있어야 한다. |
| 홈화면 선택지 개인화 | 판단된 학생 유형에 따라 홈화면 선택지가 다르게 노출되어야 한다. |
| 학습 중 코칭 분기 | 학생이 선택한 막힘 원인에 따라 챗봇 응답이 다르게 진행되어야 한다. |
| 내부 분류명 비노출 | 학생 화면에는 내부 학생 유형명이 노출되지 않아야 한다. |
