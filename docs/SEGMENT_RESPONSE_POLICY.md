# 세그먼트별 응답 정책

> PRD의 학생 유형별 코칭 방향을 실제 `ChatResponse.messages` 출력 형태로 옮기기 위한 연결 문서입니다.
> 최종 문구를 확정하는 문서가 아니라, 팀원이 세그먼트별 응답을 나눠 고도화하기 전에 공유해야 할 공통 기준을 정리합니다.

## 2. 먼저 구현할 공통 골격

한 명이 먼저 구현해도 되는 영역입니다. 세그먼트별 기획을 확정하지 않고도 만들 수 있는 기반 구조입니다.

- `text`, `choices`, `image_card`, `hint_card` 응답 builder
- TP1~TP5 노드가 공통으로 쓰는 응답 조립 helper
- `segment + grade_group + current_touchpoint` 기준 정책 선택 함수
- 케이스 1·2를 위한 기본 placeholder 응답
- 선택지 `id` 규칙과 label 노출 규칙
- 테스트 fixture와 기본 단위 테스트

이 단계의 목표는 "최종적으로 가장 좋은 말"을 만드는 것이 아니라, 팀원이 나중에 세그먼트별 응답을 안정적으로 바꿀 수 있는 구조를 먼저 여는 것입니다.

---

## 3. 팀 합의 후 고도화할 영역

아래 항목은 교육 기획과 사용자 경험의 핵심이므로 팀 합의 후 세그먼트별로 나눠 고도화합니다.

- 각 세그먼트의 실제 선택지 문구
- 학년별 말투의 구체적인 길이와 친근함 정도
- 힌트 제공 단계 수
- 정답을 언제까지 직접 제공하지 않을지
- 이미지 카드 사용 기준
- teach-back 질문의 표현 방식
- 학습 종료 시 칭찬·복습 유도 강도

---

## 4. 공통 원칙

1. 내부 세그먼트명은 학생 화면에 노출하지 않는다.
2. 정답을 바로 알려주기보다 조건 확인, 개념 이해, 풀이 단계로 유도한다.
3. 메시지 구조는 코드에서 고정하고, 세부 문구는 프롬프트와 정책 데이터로 조정한다.
4. 저학년은 짧은 문장과 선택지를 우선한다.
5. 고학년은 이유와 풀이 과정을 존중하는 코치형 말투를 우선한다.
6. 선택지 `id`는 안정적인 영문 snake_case로 두고, 학생에게는 `label`만 보여준다.
7. MVP는 기존 문제·해설·힌트 데이터를 활용하며, 새 문제 생성은 하지 않는다.

## 5. 세그먼트별 출력 방향

| 세그먼트 | 핵심 목표 | 우선 메시지 타입 | 피해야 할 것 |
|----------|----------|------------------|--------------|
| `잘함+성실` | 흥미 유지, 심화·확장 | `text` + `choices` | 이미 잘하는 학생에게 반복 설명만 제공 |
| `잘함+불성실` | 짧고 명확한 시작, 도전감 | `text` + `choices` | 긴 설득, 루틴 강요 |
| `못함+성실` | 막힘 원인 진단, 단계별 이해 | `choices` + `hint_card` + `text` | 바로 정답 제공, 실패감 강화 |
| `못함+불성실` | 진입장벽 낮추기, 즉시 성공 경험 | 짧은 `text` + 쉬운 `choices` + 필요 시 `image_card` | 긴 설명, 많은 선택지, 부담 주는 표현 |

## 6. TP별 기본 정책

### TP1. 홈화면 진입

| 세그먼트 | 출력 형태 | 방향 |
|----------|----------|------|
| `잘함+성실` | `text` + `choices` | 오늘의 심화/적용 학습을 제안 |
| `잘함+불성실` | 짧은 `text` + `choices` | 5분 도전, 이어하기처럼 시작점 축소 |
| `못함+성실` | `text` + `choices` | 쉬운 설명, 단계별 풀이, 막힘 확인으로 유도 |
| `못함+불성실` | 아주 짧은 `text` + 쉬운 `choices` | 1분/1문제/그림 보기처럼 부담 낮추기 |

### TP2. 단위 학습 완료

| 세그먼트 | 출력 형태 | 방향 |
|----------|----------|------|
| `잘함+성실` | `text` + `choices` | 성취를 인정하고 심화로 연결 |
| `잘함+불성실` | 짧은 `text` + `choices` | 완료 경험을 루틴으로 이어가기 |
| `못함+성실` | `text` + `choices` | 노력 인정, 다음 한 단계 제안 |
| `못함+불성실` | 짧은 칭찬 `text` + 작은 선택지 | 완료 자체를 크게 강화 |

### TP3. 이탈 시도 감지

| 세그먼트 | 출력 형태 | 방향 |
|----------|----------|------|
| `잘함+성실` | `text` + `choices` | 남은 학습의 의미를 짧게 안내 |
| `잘함+불성실` | 매우 짧은 `text` + 도전 선택지 | "딱 하나만"처럼 목표 축소 |
| `못함+성실` | 공감 `text` + 다음 단계 선택지 | 힘든 지점을 인정하고 단계 낮추기 |
| `못함+불성실` | 초소형 목표 `text` + 쉬운 선택지 | 남은 양을 최소화해 이탈 방지 |

### TP4. 학습 중 도움 요청

| 세그먼트 | 출력 형태 | 방향 |
|----------|----------|------|
| `잘함+성실` | `text` + `choices` | 단서 확인 후 심화 사고 질문 |
| `잘함+불성실` | 짧은 `text` + `choices` | 핵심 조건만 빠르게 잡고 도전 유지 |
| `못함+성실` | 원인 진단 `choices` + `hint_card` | 개념/조건/식/계산 중 막힘을 나눠 코칭 |
| `못함+불성실` | 쉬운 원인 `choices` + 짧은 `text` + 필요 시 `image_card` | 글/상황/답 고르기 부담을 줄이고 한 문제만 유도 |

### TP5. 오늘 학습 종료

| 세그먼트 | 출력 형태 | 방향 |
|----------|----------|------|
| `잘함+성실` | `text` + `choices` | 오늘 성취 요약, 다음 심화 예고 |
| `잘함+불성실` | `text` + `choices` | 짧게 끝낸 성취를 루틴으로 연결 |
| `못함+성실` | `text` + `choices` | 오답 복습 여부를 부드럽게 안내 |
| `못함+불성실` | 짧은 `text` + 쉬운 선택지 | 다음 학습에 대한 부담을 낮춤 |

## 7. MVP 케이스 적용

### 케이스 1 — 저학년 국어, `못함+불성실`

- 홈화면에서는 긴 학습 대신 "1분", "1문제", "그림 보기" 중심으로 진입한다.
- 학습 중 도움 요청에서는 자유 입력보다 선택지를 우선한다.
- `image_card`는 상황 이해가 막힌 경우에만 사용한다.
- 응답은 한 번에 하나의 행동만 제안한다.

### 케이스 2 — 고학년 수학, `못함+성실`

- 홈화면에서는 개념 보정과 단계별 풀이를 우선 제안한다.
- 학습 중 도움 요청에서는 원인을 `개념`, `비교 대상`, `식 세우기`, `계산`으로 나눈다.
- `hint_card`는 식 세우기나 단계별 풀이가 필요한 경우 사용한다.
- 정답을 바로 말하지 않고, 비교 대상 확인 → 식 구성 → 계산 → teach-back 순서로 진행한다.

## 8. 팀 분담 방식

세그먼트별 날카로운 기획은 아래처럼 나누는 것을 권장합니다.

| 담당 단위 | 주요 작업 |
|-----------|----------|
| `잘함+성실` | 심화/적용 선택지와 확장 질문 고도화 |
| `잘함+불성실` | 짧은 도전형 시작 문구와 루틴 유도 고도화 |
| `못함+성실` | 원인 진단, 단계별 힌트, teach-back 고도화 |
| `못함+불성실` | 초소형 목표, 쉬운 선택지, 즉시 성공 경험 고도화 |

각 팀원은 최종 문구만 바꾸는 것이 아니라, PRD의 세그먼트 목표와 `ChatResponse` 메시지 타입이 일치하는지도 함께 확인합니다.

## 9. 남은 합의 질문

- TP1 홈화면 선택지는 세그먼트별 3개로 통일할지, 케이스별 4개까지 허용할지
- TP4 도움 선택지 label을 PRD 예시와 얼마나 동일하게 유지할지
- 저학년 국어에서 이미지 카드를 어느 원인 선택지까지 사용할지
- 수학 `못함+성실` 케이스에서 teach-back을 필수 단계로 둘지
- LLM이 응답 문구를 생성하더라도 선택지 구조는 항상 deterministic하게 고정할지
