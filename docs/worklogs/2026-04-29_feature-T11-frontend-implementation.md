## 비개발자 요약 — 왜 했고 무엇을 만들었는지

### 왜 했나요?

이전 작업에서는 `docs/design/t11-concepts` 아래에 정적 HTML 시안을 만들어 디자인 방향과 화면 흐름을 비교했습니다.

이번 작업의 목적은 그 시안을 실제 프론트 개발로 이어가기 위해, 나중에 `/chat` API와 연결할 수 있는 **Next.js 기반 앱 구조**로 옮기는 것이었습니다.

중요한 방향은 아래와 같습니다.

- 프론트는 별도 챗봇 앱이 아니라 스마트올 화면 위에 붙는 **AI 학습코치 레이어**입니다.
- 홈 화면에서는 AI 코치가 말풍선으로 먼저 학습을 추천합니다.
- 학습 중에는 오른쪽 아래 AI 코치 캐릭터만 떠 있습니다.
- 학생이 캐릭터를 누르면 오른쪽 채팅 패널이 열립니다.
- 캐릭터는 드래그로 위치를 바꿀 수 있습니다.
- 실제 `/chat` API가 아직 없으므로 이번에는 mock 응답으로 화면 흐름을 검증합니다.

### 무엇을 만들었나요?

`frontend/` 폴더에 Next.js 프론트 앱을 새로 만들었습니다.

구현된 화면은 크게 세 가지입니다.

- 스마트올 `오늘의 학습` 홈 화면
- 국어/수학 학습 화면
- 단위 학습 완료 및 오늘 학습 마무리 화면

AI 코치 UI는 두 가지 방식으로 보입니다.

- 짧은 추천: 캐릭터 위 플로팅 말풍선
- 학습 도움: 오른쪽 채팅 패널

## 구현 상세

### 1. Next.js 앱 생성

아래 기준으로 `frontend/` 앱을 만들었습니다.

```text
Next.js 16.2.4
React 19.2.4
TypeScript
Tailwind CSS
App Router
src/ 디렉터리 구조
npm
```

실행 명령은 아래와 같습니다.

```powershell
cd frontend
npm run dev
```

브라우저에서는 보통 아래 주소로 확인합니다.

```text
http://localhost:3000
```

검증 중에는 IPv4 주소를 고정하기 위해 아래 주소도 사용했습니다.

```text
http://127.0.0.1:3000
```

### 2. 화면 상태 구조

현재 프론트는 하나의 화면에서 케이스와 터치포인트를 전환할 수 있습니다.

케이스:

- `1~2학년 국어`
- `5~6학년 수학`

상태:

- `홈 추천`
- `학습`
- `도움`
- `완료`
- `이탈`
- `마무리`

이 구조는 실제 서비스 UI라기보다, 발표와 내부 확인을 위해 TP 흐름을 빠르게 전환하는 시연 장치입니다.

### 3. AI 코치 캐릭터

AI 코치는 화면 오른쪽 아래에 떠 있는 캐릭터 레이어로 구현했습니다.

- 기본 위치: 오른쪽 아래
- 동작: 클릭 시 오른쪽 채팅 패널 열림
- 드래그: pointer event로 위치 이동
- 드래그 중: 캐릭터가 손가락에 매달린 듯한 흔들림 애니메이션
- 패널 열림 상태: 채팅 패널 버튼을 가리지 않도록 왼쪽으로 살짝 이동

현재 캐릭터는 실제 에셋이 아니라 CSS로 만든 임시 캐릭터입니다.
나중에 PNG/WebP, Lottie, Rive 등으로 교체할 수 있도록 `CoachLayer` 내부에 분리했습니다.

### 4. 메시지 렌더링

백엔드 `app/schemas/chat.py`의 응답 구조를 프론트 타입으로 옮겼습니다.

현재 렌더링되는 메시지 타입:

- `text`: 일반 코치 메시지
- `choices`: 선택지 버튼
- `image_card`: 저학년 국어 상황 이해용 이미지 카드
- `hint_card`: 고학년 수학 단계별 힌트 카드

아직 실제 `/chat` 호출은 하지 않습니다.
대신 `mockChatAdapter`가 같은 응답 형태를 반환하도록 만들었습니다.

## 서버와 localhost 확인 이슈

작업 중 검증을 위해 제가 백그라운드에서 `next start` 서버를 띄웠습니다.

```powershell
npm run start -- --hostname 127.0.0.1 --port 3000
```

검증 후 서버를 종료했지만, 사용자가 브라우저에서 `http://localhost:3000` 화면이 계속 보인다고 알려주었습니다.

확인한 내용:

- `127.0.0.1:3000` 서버 프로세스는 종료됨
- `localhost:3000`도 `curl` 기준 연결 거부 확인
- `::1:3000` IPv6도 연결 거부 확인
- `netstat` 기준 3000번 포트 `LISTEN` 없음
- `next`, `npm` 서버 프로세스 없음
- 남은 `TIME_WAIT` 연결은 OS가 정리하는 종료 흔적

가능성이 높은 원인:

- 브라우저가 이미 받은 React 앱을 탭 메모리에서 계속 보여주는 상태
- 이전 `localhost:3000` 서비스워커나 캐시가 남아 있는 상태

사용자에게 안내한 확인 방법:

- Chrome 개발자도구 `Application` 탭에서 `Service Workers` 확인
- `localhost:3000` 관련 서비스워커가 있으면 `Unregister`
- `Clear storage`에서 `Clear site data`
- 새 탭 또는 시크릿 창에서 다시 접속

## SSE 설명 정리

사용자 질문에 따라 SSE의 필요성도 정리했습니다.

SSE는 `Server-Sent Events`의 줄임말입니다.
챗봇 답변을 한 번에 받는 대신, 서버가 만든 문장이나 메시지를 순서대로 조금씩 보내는 방식입니다.

### SSE가 없을 때

```text
학생 클릭
→ 서버가 답변 전체를 다 만들 때까지 기다림
→ 완성된 답변이 한 번에 표시됨
```

### SSE가 있을 때

```text
학생 클릭
→ 서버가 만든 메시지를 순서대로 조금씩 보냄
→ 학생은 AI 코치가 바로 반응하는 것처럼 느낌
```

### 이번 T11에서의 판단

이번 작업은 mock 프론트 검증이므로 SSE가 없어도 화면 흐름 확인은 가능합니다.

하지만 T10 `/chat`이 구현되고 실제 LLM 응답을 받기 시작하면, 아래 이유로 SSE가 필요합니다.

- 긴 답변을 기다리는 시간을 줄여 보이게 함
- 코치가 바로 반응하는 느낌을 줌
- 단계별 힌트나 메시지를 순차적으로 보여줄 수 있음
- 실제 챗봇다운 경험을 만들 수 있음

## 현재 상태

현재 기준으로 T11은 아래 상태입니다.

```text
mock 프론트 구현: 완료
실제 /chat 연동: 미완료
SSE 수신: 미완료
학생 선택 드롭다운: 미완료
실제 캐릭터 에셋/정교한 애니메이션: 미완료
```

다음에 이어서 하면 좋은 작업:

1. 채팅 선택지를 눌렀을 때 사용자 선택 말풍선과 다음 mock 응답이 바로 보이게 개선합니다.
2. 실제로 눌리는 버튼과 장식용 버튼을 시각적으로 구분합니다.
3. 학생 선택 드롭다운을 추가합니다.
4. T10 `/chat`이 준비되면 mock adapter를 실제 API adapter로 교체합니다.
5. SSE 응답을 메시지 타입별로 순차 렌더링합니다.
