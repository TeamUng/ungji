# Worklog — feature/T3-prompts-tests

## 작업 배경

T3 프롬프트 구현은 완료되어 있었지만, 학년별 페르소나와 세그먼트별 코칭 전략이 PRD 케이스 1·2 방향을 계속 만족하는지 보호하는 테스트가 없었다.
앞으로 팀원이 세그먼트별 응답을 고도화하면서 프롬프트 문구를 수정할 가능성이 높으므로, 최소한의 기획 방향이 깨지지 않도록 회귀 테스트가 필요했다.

## 왜 필요한가

- PRD는 학년별 말투와 세그먼트별 코칭 전략을 명확히 나누고 있다.
- T5~T7 노드가 프롬프트를 조합해 응답을 만들 예정이므로, 프롬프트 함수가 빈 값이거나 엉뚱한 방향이 되면 이후 노드 품질이 함께 흔들린다.
- MVP 핵심 케이스인 케이스 1과 케이스 2는 프롬프트 방향이 특히 중요하다.

## 구현 방법

- `GradeGroup` 전체와 `Segment` 전체를 parametrized test로 순회했다.
- 반환값이 문자열이고 비어 있지 않은지 검증했다.
- 케이스 1은 `lower + 못함+불성실` 조합으로, 짧은 말투·초소형 목표·즉시 성공 경험 방향을 확인했다.
- 케이스 2는 `upper + 못함+성실` 조합으로, 차분한 코치형 말투·막힘 원인 진단·단계별 설명·정답 직접 제공 지양·teach-back 방향을 확인했다.
